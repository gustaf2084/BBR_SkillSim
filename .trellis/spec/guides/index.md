# 思考指南(BBR_SkillSim)

> **目的**:写代码前多想一步,抓出"没想到"的问题 —— 大多数 bug 和欠债来自"没想到",而不是没能力。

---

## 可用指南

| 指南 | 用途 | 何时使用 |
|------|------|----------|
| [代码复用思考指南](./code-reuse-thinking-guide.md) | 识别重复、减少重复 | 发现重复模式、新增工具函数前 |
| [跨层数据流思考指南](./cross-layer-thinking-guide.md) | 想清楚 model ↔ view 的数据流与边界 | 改动跨越 GameData/引擎/UI 多层 |

## 快速触发表

### 何时该读跨层指南

- [ ] 改动同时涉及 `data.json` 数据、引擎计算、UI 展示中的两层以上
- [ ] 新增/修改跨线程共享的数据(GameData、引擎结果)
- [ ] 新 tab 或新页面要消费引擎输出
- [ ] 拿不准某段逻辑放 model 还是 view
- [ ] 改动了 `on_data_ready` / `retranslate` / `retheme` 的调用链

→ 读 [跨层数据流思考指南](./cross-layer-thinking-guide.md)

### 何时该读代码复用指南

- [ ] 要写一段"类似已有代码"的逻辑(权重合成、概率计算、双语访问、路径解析)
- [ ] 同一模式出现 3 次以上
- [ ] **要改任何常量**(颜色 token、i18n 词条、`SETTINGS_FILE`、版本号)
- [ ] **要新建工具/辅助函数** ← 先搜索!
- [ ] 要在 UI 里直接读 `GameData` 的 dict 字段(应先找访问器)
- [ ] 逆向推导相关改动(先想能不能复用 `forward_simulate()` 缓存)

→ 读 [代码复用思考指南](./code-reuse-thinking-guide.md)

## 改值前先搜索(关键规则)

> **改任何值之前,先搜索它在哪些地方被使用!**

```bash
rg "要改的值" src/ tests/
```

这一条习惯能防住大多数"忘了同步更新 X"的 bug(历史教训:概率显示格式、settings 路径、颜色字面量)。

## 如何使用本目录

1. **写代码前**:扫一眼相关指南
2. **写代码时**:感到重复或复杂,查指南
3. **出 bug 后**:把新教训补进相关指南(learn from mistakes)
